## Purpose and rationale

`JsonapiView::displayList()` discovers attributes from the objects returned by
the view's dynamic get. An empty collection has no objects, leaving the field
list empty. Joomla constructs `onApiGetFields` before serializing even an
empty collection, and `OnGetApiFields::setFields()` rejects that empty list.

The discovery assignment is literal text in these compiler templates, rather
than a fragment generated by a library renderer. Both templates therefore
need the same fallback before `parent::displayList($items)`. A library-only
change would leave the invalid assignment in generated API views.

## Implementation details

### `admin/compiler/joomla_4/API_DYNAMIC_VIEWS_JSON.php`

- **Change type:** Modified
- **Stable location(s):** Generated `JsonapiView::displayList()`, assignment
  to `$this->fieldsToRenderList` immediately before
  `###API_DYNAMIC_VIEWS_JSON_META###`.
- **What changed:** Use `array_keys($fields) ?: ['id']` instead of
  `array_keys($fields)`. Preserve the metadata placeholder and parent call.
- **Why:** Supply nonempty field metadata for an empty collection while
  retaining the runtime-discovered attributes for populated collections.
- **Related paths/symbols:** `Compiler\Config::getJoomlaversions()` selects
  this template family for Joomla 4 and 5;
  `Compiler\Component\Structuremultiple::buildDynamicApi()` builds site
  and custom administrator dynamic list resources from it;
  Joomla `JsonApiView::displayList()` and `OnGetApiFields::setFields()`.

### `admin/compiler/joomla_6/API_DYNAMIC_VIEWS_JSON.php`

- **Change type:** Modified
- **Stable location(s):** Generated `JsonapiView::displayList()`, assignment
  to `$this->fieldsToRenderList` immediately before
  `###API_DYNAMIC_VIEWS_JSON_META###`.
- **What changed:** Apply the identical `array_keys($fields) ?: ['id']`
  fallback, preserving the metadata placeholder and parent call.
- **Why:** Prevent the same empty-field event exception in Joomla 6 API views.
- **Related paths/symbols:** `Compiler\Config::getJoomlaversions()` selects
  this template family for Joomla 6; the structure builder and Joomla API
  classes are the same consumers described above.

## Impact

- **Behavioral impact:** Valid empty dynamic list resources can complete
  Joomla's normal success path, returning HTTP 200 and `data: []`. The
  fallback supplies serializer metadata, not a dummy item or ID value.
  Populated responses retain their discovered field union, including fields
  added by preparation, joins or custom processing. Normal model error,
  permission, missing-item and invalid-pagination handling remains active.
- **Visual impact:** None; no administrator view, layout, field or browser
  script changes.
- **Accessibility impact:** None; no user interface changes.
- **Compatibility impact:** Generated Joomla 4/5 code uses `joomla_4` and
  Joomla 6 code uses `joomla_6`. There is no Joomla 3 API template change.
- **Generated-output impact:** The one assignment changes in each generated
  `api/src/View/<Name>/JsonapiView.php` belonging to a site or custom
  administrator list dynamic get. Existing installed components need
  recompilation and installation to receive it. Generated paths, API routes,
  placeholders and nonempty response shapes stay unchanged.

## Risks, limitations, and rollback

- **Known risks:** The fallback activates only when no object fields were
  discovered. It does not replace or narrow populated response fields.
- **Known limitations:** This correction does not turn real database errors
  into empty results, change missing-item semantics, or alter Joomla's
  out-of-range pagination contract. Existing installed output remains
  affected until recompiled or patched.
- **Rollback:** Revert this change's commit, restoring the original
  `array_keys($fields)` assignments in both templates together with their
  regression and record. Previously installed compiled components change
  only after another compile/install or an explicit generated-file patch.
