# 6.2.0 test audit

This audit follows the import of JCB's generated stable component at
`f748af3b0ebf6ae319571b3cce86f0f76c8c2c86` and the first maintenance implementation
at `222f71228846d6ec99a3628dc7b10854d24bea63`. Green checks on that implementation
did not mean every imported behavior was covered. The audit checked executable
coverage, test assertions, native Joomla lifecycle boundaries, shipped
administrator classes, and the identity of installed test packages.

## Coverage measurement and its limits

The PHP 8.4 Clover artifact from
[run 37684063897](https://github.com/extension-builder/joomla/actions/runs/37684063897)
measures commit `222f71228846d6ec99a3628dc7b10854d24bea63`, **before the additional
tests and corrections described below**. These are attributed statement counts,
not branch coverage or estimates based on test ownership.

| Measured source scope | Covered statements | Total statements | Coverage |
| --- | ---: | ---: | ---: |
| Configured first-party library source | 53,007 | 88,659 | 59.79% |
| The 12 library files changed by the initial maintenance work | 1,627 | 2,169 | 75.01% |
| Changed executable statement locations in those files | 183 | 191 | 95.81% |

To reproduce the first row, download that run's PHP 8.4 coverage artifact and
read `project/metrics` in `clover.xml`: `coveredstatements` and `statements` are
the numerator and denominator. For the second row, select Clover files named
by `git diff --name-only f748af3 222f712` under the configured production source
directories and sum each file's same metrics. For the third, intersect Clover
`line` entries with `type="stmt"` with the new-side hunk ranges from
`git diff --ignore-space-at-eol --unified=0 f748af3 222f712`; count entries whose
execution `count` is greater than zero. Pin both revisions when repeating the
calculation, rather than comparing a newer working tree with the old artifact.

Four unattributed changed statements were in keyword normalization and one in
the malformed-attribute parser guard. The additional tests below cover those
behaviors. Two other locations were provider construction lines exercised by
an existing real-container test but outside that test's coverage attribution.
The remaining location is the `Crypt.FOF` provider construction line. An
unattributed statement is not automatically evidence that it never runs.

The ownership gate assigns each production declaration a meaningful owner; it
does not establish complete method, statement, or branch coverage. The three
documented legacy compiler helper exclusions remain excluded. Evaluated
generated PHP, shipped administrator code outside the library source filter,
browser journeys, and installed API requests are separate evidence. The
configured library percentage therefore neither measures all deployed JCB code
nor proves that every component area is fully tested.

## Independent regression and negative-control checks

On 7 October 2026, the SearchQuery, search-batching, Power parser and Markdown
changes were independently checked at candidate
`222f71228846d6ec99a3628dc7b10854d24bea63` against the synchronized source baseline
`f748af3b0ebf6ae319571b3cce86f0f76c8c2c86`. The four complete affected PHPUnit
classes passed **96 tests and 3,131 assertions** on PHP 8.3.6 with the pinned
Joomla 6.1.2 test runtime; documented unrelated known-defect tests were excluded.

A passing candidate alone is insufficient evidence of a regression test.
Selected current tests were therefore rerun against actual baseline production
files and against deliberately incorrect candidate files. Composer class-map
overrides loaded those files from isolated temporary copies. The shared
production checkout was never reverted or mutated. Each negative-control run
started in a separate PHP process with result caching disabled.

| Contract | Candidate tests passing | Baseline tests failing | Deliberate mutation and detected failures |
| --- | ---: | ---: | --- |
| Folder and genuine joined-column search | 8 | 7 | Drop all valid joined display-column predicates: 1 failure |
| Complete batched record traversal | 9 | 8 | Reverse the ID ordering while keeping the ascending cursor: 8 failures |
| Complete DNF metadata and safe parameter boundaries | 5 | 5 | Narrow a DNF parameter type to `null`: 4 failures |
| Images, links and URL policy | 19 | 19 | Remove the image-attribute exclusion from link parsing: 1 failure |

The failures protect observable behavior. The old 600-record loader cannot
complete its bounded traversal; it does not merely emit a differently formatted
query. The old parser loses DNF properties and accepts unsupported parameter
suffixes. Removing image exclusion corrupts an image's alternative-text
attribute and the following link. Removing valid joined predicates loses the
related display-column search while local search remains present.

The tests run production renderers, cursor handling and storage decoding.
Database and query doubles model the external boundary: the batching fixture
actually filters, sorts and limits deterministic rows according to the query
received, while expected IDs come independently from the complete input dataset.
The parser and Markdown cases assert independently written metadata or complete
rendered output. Search provider coverage also verifies shared injected registry
identity through subsequent state changes and their effect on generated output.

## Additional source-to-output guard coverage

The audit identified one missing source-to-rule check: model validation tests
already exercised normalized case-insensitive keyword rules, but did not prove
that authored mixed-case keywords reached both consumers consistently.
`AdminViewScriptTest::testMixedCaseKeywordsProduceMatchingBrowserAndServerRules`
now starts with `keywords="Red, BLUE"` and verifies the actual normalized
validation registry and emitted browser predicates for both all-keyword and
any-keyword matching. Skipping normalization in an isolated source copy fails
both cases.

`ParserTest::testParserRejectsIncompleteAttributeWithoutChangingOtherArgumentTypes`
now checks the incomplete-attribute guard through the public parser. It rejects
the malformed argument without discarding a preceding valid integer argument or
changing a following method's nullable reference and union types. Replacing
argument-level rejection with an early `null` return fails the test.

These three additional cases pass **13 assertions**. Both updated test classes
pass **42 tests and 159 assertions** together. The changed-file PHP style guard
and scoped Git whitespace check also pass. No coverage percentage is inferred
from declaration ownership or these test counts.

## Native lifecycle and imported component checks

The following gaps were found by inspecting the actual synchronized source and
running focused behavioral checks. Assertions target output, authorization,
validation, persistence, and failure behavior; they do not merely check class
existence.

| Area | Audit finding and protection |
| --- | --- |
| API tag preservation | Joomla adds an empty tag array after validation when a tag field is absent. If ACL or a validation plugin removes, disables, or unsets that field, this default can erase existing relations. Generated `getForm()` and `save()` retain the actual form policy and discard that manufactured default for omitted or forbidden PATCH tags. Explicit, permitted empty arrays still clear tags. |
| Composed PATCH lifecycle | `GeneratedPatchLifecycleTest` combines generated controller/model methods with native Joomla form validation and `AdminModel::save()`. Its 19 cases and 465 assertions cover repeated updates, raw storage preservation, tag policy, invalid explicit values, native failures, and non-PATCH behavior. Application, persistence, and event boundaries are controlled; this is not a live database test. |
| Conditional validation | Raw selectors can differ from Joomla-filtered selectors; before-validation plugins can change both data and form policy. Nested groups and omitted unchecked administrator checkboxes also differ from partial API input. The lifecycle regressions exercise these distinctions and require native filtering and validation to remain authoritative. |
| Standalone access-denial messages | Generated guards referenced a JCB language key absent from standalone generated extensions. The tests now load core Joomla language only, and the renderer uses `JERROR_ALERTNOAUTHOR`. |
| Shipped controller ownership | `ShippedControllerOwnershipTest` runs the actual 51 imported form controllers, checking stored ownership, forged posted ownership, missing records, and record/component ACL combinations. |
| Shipped view output | `ShippedViewEscapingTest` runs 108 imported view classes, checking plain-text sanitization, inherited Joomla HTML escaping, attribute delimiters, and full-length labels. Together, the two shipped-class suites pass 159 cases and 5,523 assertions. |
| Browser assertions | Radio helpers must assert the requested checked state, and unmatched searches must always assert their empty result. New Compiler and Field journeys check target choices, missing-component feedback, and expert-storage requirement toggles through the actual controls. These journeys require the hosted browser run. |

Preservation does not bypass existing `prepareTable()`, table checks, or authored
save hooks. The composed test explicitly verifies that audit fields and version
counters advance and existing name canonicalization still runs. An omitted
field is protected from the compiler's accidental defaulting or repeated
storage encoding; it is not exempted from intentional native or authored
persistence behavior.

Production corrections remain in the narrow compiler architecture domains.
Dependencies use the existing service-provider and registry contracts; target
selection stays in providers. The audit adds no mass rewrite of generated
administrator output. Changed-file style, declaration ownership, container-key,
moved-condition, generated-output, and installed checks remain separate gates.

## Known-defect lane and installed-test integrity

The Joomla 6 toolbar contract had recovered during the stable import but remained
in the non-blocking known-defect group. It is now part of the normal versioned
toolbar matrix. The remaining **84 existing cases** still represent documented
debt, not passing coverage. The focused audit found no further clean recoveries;
some cases pass assertions while emitting runtime diagnostics.

CI now audits individual PHPUnit case events. A clean passing case must leave
the known-defect group even if its siblings still fail. Warnings, notices,
deprecations, risky-test diagnostics, and incomplete reports cannot masquerade
as clean recoveries. The checker is tested with separate real PHPUnit runs;
the existing defect lane remains visible and non-blocking, while its recovery
audit is blocking. See [the testing guide](testing.md#known-defect-debt-ledger)
for the retained debt and reproduction commands.

API and GUI harnesses now verify installed runtime files against SHA256
manifests derived from their actual package archives, including administrator
controllers/models/views/templates, API files, compiler templates, and shipped
JCB libraries. Before authentication, a fresh exact-response proof ties the
HTTP endpoint to that verified installation. API readiness also checks a free
port and the newly started server process; compiler failures are no longer
ignored merely because a ZIP exists. Offline negative cases cover tampering,
missing files, incorrect HTTP targets, redirects, occupied ports, and dead
processes. [Integration provenance](../../.github/test-infra/README.md) documents
the mapping, retained evidence, and exclusions. These checks prove which files
were exercised; they do not turn those files into complete behavioral coverage.

## Evidence boundaries

At the audit checkpoint on 8 October 2026, the complete local blocking suite
passed **4,777 tests and 57,843 assertions** on PHP 8.3.6. The contribution-style,
whitespace, ownership (1,487 declarations), container-key, and moved-condition
checks passed. The independent golden harness self-checks passed 40 cases;
installed-provenance negative tests passed 19 cases.

The installed API run at `9a69230802f23bb7998d94316fc671f200cc0aa5`
([run 37741432769](https://github.com/extension-builder/joomla/actions/runs/37741432769))
passed **100 partial-PATCH checks, 100 existing API scenarios, and 22 permission
checks** across both resource names. Its newly generated conditional fields
prove that rule registration, generation, installation, native INT filtering,
rejection of forged `not_required`, and preservation of omitted active values
work together. This supplements the native lifecycle unit tests; it does not
replace the separate browser and full-tree compiler gates.

At the same revision, both hosted PHP 8.3/8.4 jobs passed
([run 37741432773](https://github.com/extension-builder/joomla/actions/runs/37741432773)),
and all **29 browser tests** passed
([run 37741432792](https://github.com/extension-builder/joomla/actions/runs/37741432792)).

- Search tests execute emitted PHP against query doubles and check predicates,
  escaping and retention of existing access conditions. They do not establish
  live MySQL result sets or installed administrator-list behavior.
- The parser checks metadata and preservation of other parsed members. They do
  not, by themselves, establish a complete Extrusion import/export round trip.
- The public Hello World compiler golden fixture is not a JCB self-compilation.
  That stronger claim requires the maintainer's complete JCB definition package
  and a measured compile of that package.
- The shipped `admin/src/Model/Help_documentsModel.php::getListQuery()` still
  contains `g.` and `h.` search references without column names. The compiler
  correction prevents those invalid folder-selector predicates in regenerated
  output, but does not repair already-generated administrator models. The
  maintained JCB definitions need release regeneration and an installed Help
  Documents search check. Current green compiler tests must not be described
  as proof that this shipped search is fixed.
- The negative controls are targeted evidence that these assertions detect the
  known defects and representative incorrect repairs. They are not an exhaustive
  mutation analysis, proof of complete branch coverage, or a replacement for
  full-suite, generated-output and installed acceptance gates.
