## Implementation decisions

- **1118:** `Compiler/Architecture/CustomView/Form::siteAction()` appends the
  configured frontend view to the Joomla 3/4/5 form action. Joomla 6 already uses
  `Route::_('index.php')`, which preserves the parsed current route through
  Joomla's router; adding an explicit component option there would disable that
  inheritance. Its version-specific implementation is deliberately retained.
- **1123:** `Compiler/Power/Injector::addLines()` previously searched beyond the
  class boundary and could inject an import as an invalid trait reference inside
  a class. PHP token offsets now identify the full named declaration, including
  its docblock, attributes and modifiers. Existing import resolution, alias
  collision handling and Joomla Power placeholders remain in their established
  pipeline; no blanket raw URI import is added to templates.
- **1283:** `Server/Ftp` passes the parsed connection settings instead of
  undefined variables, checks connect/login results and translates FTP transfer
  modes. `Server/Sftp` checks authentication, preserves exact secret values and
  respects relative, absolute and root destinations. `Server/Model/Load` removes
  only legacy NUL padding after decryption. The injected `Server.ClientFactory`
  is the protocol-construction boundary; transport services keep their existing
  identities and direct construction remains compatible.
- **1309:** The user's compiler/manual-save distinction was verified in source.
  `Compiler/Language/Insert` formerly omitted the nullable translation column;
  it now appends `translation = ''` when rendering SQL, preserving the existing
  seven-value queue. The working manual-save method is unchanged. `FilterHelper`
  also handles legacy SQL NULL, empty and malformed JSON, and matches exact
  language entries with nonblank values (including `"0"`). The list model includes
  its custom filters in the cache identity and rejects malformed selections.
  This host-side persistence/filter behavior does not select a compiler target.
