# User-interface language strings

This project carries two different language-string conventions, and the
difference is deliberate. Which one applies depends on where the string
lives.

## Generated and long-standing admin code: language constants

The historic admin views (the compiler view, the search view, the list and
edit views) were generated by JCB itself, and their strings are language
constants — `Text::_('COM_COMPONENTBUILDER_COMPILE_COMPONENT')` — defined in
`admin/language/en-GB/*.ini`. Leave that convention exactly as it stands in
the files that already use it.

## New hand-written view code: natural strings, untransformed

New views written by hand for import back into JCB (the extrusion view is
the first) follow JCB's own authoring convention instead:

- Every user-facing string is written as a **natural sentence inside
  `Text::_()`**:

  ```php
  echo Text::_('Harvest the source');
  ```

- The string is **never transformed into a language constant**, and it is
  **never added to the language `.ini` files**. JCB detects natural strings
  inside `Text::_()` (and `Text::sprintf()`) when the code is imported, and
  moves them into its own language management from there. Constants added by
  hand would collide with that pipeline and double the maintenance.

- The same rule holds for **JavaScript**. Scripts never carry user-facing
  English of their own; they receive their strings through a map the
  template prints, where each entry is again a natural string inside
  `Text::_()`:

  ```php
  text: { harvesting: '<?php echo Text::_('is being harvested', true); ?>' }
  ```

  (The second argument makes the string safe to embed in a script.)

- **Structural constants are the one exception.** Strings that Joomla itself
  resolves outside the view — menu entries in the manifest, submenu entries,
  dashboard tiles, and the ACL action titles in `access.xml` — must be
  constants, because Joomla looks them up by key before any view runs. Those
  few constants do go into the `.ini` files, and nothing else does.

The engine side of the same work (everything under
`libraries/vendor_jcb/VDM.Joomla/**`) returns plain-language messages as
data (see the Extrusion `Registry\Message` bus) and never calls `Text::_()`
at all; the view layer is where language begins.
