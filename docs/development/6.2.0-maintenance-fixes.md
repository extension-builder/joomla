# JCB 6.2.0 maintenance fixes

This branch implements the approved follow-up to the established JCB 6 defect
review, based on stable commit `f748af3b0ebf6ae319571b3cce86f0f76c8c2c86`.

## Scope

- Preserve omitted API PATCH data, including storage transformations and
  collection defaults, through generated Joomla controller/model code.
- Evaluate conditional required fields on the server from compiler conditions.
- Restrict joined-column search to real generated joins while preserving local
  columns and valid relation searches.
- Exclude ACL-denied created metadata from API validation without changing
  administrator disabled controls or record edit authorization.
- Restore ID ordering for ID-cursor search batches and exercise complete batch
  traversal with reversed titles, duplicate titles, and sparse IDs.
- Support complete DNF property and parameter types with a narrow parser change
  and compatibility regressions.
- Correct Markdown image/link conversion and promote the regression into the
  normal test suite.

The Health Check permission correction is reserved for the maintainer and is
not part of this branch. The separately reported upstream Language Translation
failure is also outside this change.

## Review and validation

Changes are split into focused commits on one branch. Compiler fixes belong in
the shared generation path, with target behavior verified for affected Joomla
versions. Protected template changes carry their required GUI change record.
Generated administrator output is not treated as the authoritative compiler fix.

## Implementation boundaries

API preprocessing uses Joomla's normal controller hook and the model's decoded
input representation. The generated save method separately preserves the exact
stored bytes of omitted columns, avoiding JSON scalar loss, Base64 double
encoding and unnecessary re-encryption. Presence uses `array_key_exists`, so
explicit empty/null/zero values remain input and ordinary validation still
applies. Removed ACL fields are not reintroduced. Custom before-save derivations
and ordered expert-field transformations remain authoritative.

Conditional validation uses the browser renderer's normalized groups without
trusting the client's `not_required` list. Inactive values remain available;
server-side rules decide which requirements apply. Existing browser JavaScript
output is unchanged.

The list-search correction preserves every local `a.field` predicate and the
`id:` path. It adds a joined display predicate only when the matching custom
field satisfies the same storage method and table metadata as the join
renderer. Folder selectors no longer generate references to nonexistent joins.

The parser change is limited to complete DNF property and parameter types. It
does not replace the structural scanner or broaden return-type parsing.
Before/after metadata for all 1,822 existing PHP sources matched exactly.

The stable import also exposed pre-existing test-fixture drift and a genuine
`Crypt.FOF` provider/constructor mismatch. Their corrections are separate
commits; [the fixture reconciliation record](6.2.0-test-fixture-reconciliation.md)
explains the source and raw-byte evidence.
